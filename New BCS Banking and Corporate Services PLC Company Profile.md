## 5. BCS Project Approach

BCS runs enterprise projects with a proven, business-driven approach. It is adapted from the Oracle Unified Methodology (OUM) for Business Flows and the PMI Project Management Standards. We do not treat implementation as a purely technical installation of software features. Instead, we build delivery around end-to-end Business Flows, bringing together People, Process, and Technology to drive measurable operational results.

### 5.1 Core Value Drivers

- **Speed, Value, and Simplicity:** Pre-configured business process flows and standard templates shorten design cycles and speed up return on investment.
- **Process-First Alignment:** Business requirements guide system configuration, so workflows match real operational needs and regulatory standards.
- **Continuous Stakeholder Engagement:** Early hands-on checks through Conference Room Pilots (CRPs) reduce late rework and build ownership inside your team.
- **Milestone-Driven Accountability:** Clear phase gates link each deliverable to a quality sign-off and a predictable schedule.

### 5.2 The Three Pillars of BCS Delivery ("The 3 A's")

| Pillar | What It Means |
| --- | --- |
| Accelerators | Standard business process models, pre-built templates, and shared implementation toolkits that shorten delivery timelines. |
| Architecture | A unified, scalable data model built for high availability, smooth third-party integration, and well-tuned server and cloud infrastructure. |
| Adoption | Structured Organizational Change Management (OCM), role-based training, and knowledge transfer, so your teams can work on their own after go-live. |

### 5.3 Deployment Strategy Options

We match the rollout sequence to your operational risk, resource capacity, and business priorities.

| Option | How It Works | Best When |
| --- | --- | --- |
| Phased / Wave Rollout (recommended for multi-departmental scopes) | Functional areas go live in logical waves. For example, Wave 1 covers Core Finance, Procurement, and Inventory. Wave 2 covers HR, Payroll, Operations, and Advanced Analytics. This reduces disruption, brings early value, and lets teams apply lessons to later waves. | The scope covers many departments. |
| Big-Bang / Single-Wave Rollout | All in-scope modules go live at the same time. | Departments depend so closely on each other that running the old system in parallel is not practical. |

### 5.4 Project Management and Control Framework

To protect timelines, budgets, and quality against scope creep and operational risks, BCS pairs its implementation lifecycle with PMI-aligned project controls.

- **Scope and Change Control:** Any change to agreed requirements after Phase 2 sign-off follows a formal Change Request (CR) process. It assesses the impact on time, cost, and architecture before the Steering Committee approves it.
- **Risk and Issue Management:** We keep a live RAID Log (Risks, Assumptions, Issues, and Dependencies). Both Project Managers review it every week, so risks are handled early.
- **Quality Assurance:** Every deliverable goes through internal BCS peer review before it is submitted to you and before formal acceptance testing.

## 6. BCS Implementation Methodology: Five-Phase Lifecycle

BCS organizes every project into five structured phases. Each phase ends with formal deliverable reviews and a Phase-Gate Sign-Off before the next phase starts. Exact scope boundaries and acceptance criteria are set in the Project Charter at project kickoff.

### 6.1 Lifecycle at a Glance

| Phase | Core Objective | Gate Sign-Off |
| --- | --- | --- |
| 1. Definition | Set up governance, confirm scope, and baseline current processes. | CRP 1 |
| 2. Elaboration and Analysis | Design the future operating model and finalize the technical architecture. | CRP 2 |
| 3. Design and Build | Configure the solution, build approved extensions, and prepare data migration. | CRP 3 / SIT |
| 4. Transition | Confirm system readiness, migrate live data, train users, and cut over. | UAT Acceptance Certificate |
| 5. Production | Stabilize live operations, hand over to support, and plan future improvements. | Project Closure |

### 6.2 Phase 1: Definition

**Objective:** Set up governance, confirm scope, and baseline current-state processes.

**Key activities**

- Hold the kickoff and finalize governance rules.
- Gather and map baseline business requirements.
- Demonstrate baseline system flows (CRP 1).

**Gate exit deliverables**

- Approved Project Charter
- Project Management Plan and Schedule
- Inception and Requirements Report
- CRP 1 Sign-Off

### 6.3 Phase 2: Elaboration and Analysis

**Objective:** Design the future-state operating model and finalize the technical architecture.

**Key activities**

- Run a Fit-Gap analysis against standard flows.
- Define To-Be business processes and controls.
- Validate configured prototypes (CRP 2).

**Gate exit deliverables**

- Future Business Model (To-Be)
- Solution and Technical Architecture
- Fit-Gap and Customization Register
- CRP 2 Sign-Off

### 6.4 Phase 3: Design and Build

**Objective:** Configure the solution, build approved extensions, and prepare data migration.

**Key activities**

- Configure the core application modules.
- Develop and unit-test extensions and integrations.
- Map and cleanse legacy master and transactional data.
- Run end-to-end integration testing (CRP 3).

**Gate exit deliverables**

- Configured System Environment
- Custom Extensions and APIs
- Data Migration Mapping and Scripts
- CRP 3 / SIT Sign-Off

### 6.5 Phase 4: Transition

**Objective:** Confirm system readiness, migrate live data, train users, and cut over.

**Key activities**

- Train Super Users and End Users.
- Run mock and final data migration.
- Support client-led User Acceptance Testing (UAT).
- Carry out the production cutover checklist.

**Gate exit deliverables**

- Training Manuals and Completion Logs
- Reconciled Data Migration Report
- Formal UAT Acceptance Certificate
- Live Production Cutover

### 6.6 Phase 5: Production

**Objective:** Stabilize live operations, hand over to support, and plan future improvements.

**Key activities**

- Provide hypercare and post-go-live stabilization.
- Move to SLA-backed Help Desk support.
- Hold a post-implementation review.

**Gate exit deliverables**

- Operational Production System
- Support and Maintenance Handover
- Continuous Improvement Roadmap
- Project Closure Sign-Off
